# 詳細設計の技術確認記録

確認日：2026-11-01

## 1. 範囲

2～6節はPlaywriter CLI 0.9.0を使い、ポート9223のChromeで新規作成した `about:blank` のタブだけを使用した。これらの確認では外部サイトへの遷移・実記事の取得・入力JSON更新は行っていない。実記事の追加読取は8節に分けて記録する。作業タブとセッションは確認後に終了した。

本記録は設計上の小さな技術確認であり、本番実装・Pillowの画像デコード・自動テストスイート・exeの動作結果ではない。2～6・8節はブラウザ内の確認、7節はPythonによるWindowsファイル操作の確認である。試行コードはOS一時領域で実行し、本番コードとしてリポジトリへ追加していない。

## 2. data URI・blobのバイト列取得

固定の1ピクセルPNG用ダミーバイト列を用い、data URIと、同じデータから作成したblob URLをそれぞれページ内fetchで読み取った。

| 観点 | data URI | blob URL |
| --- | --- | --- |
| 応答ステータス | 200 | 200 |
| 元バイト列との全バイト一致 | 一致 | 一致 |
| PNG先頭8バイトの署名 | 一致 | 一致 |

検証用に作成したblob URLだけをrevokeした。取得バイト列とURLは記録へ保存していない。失効blob・期限切れ・巨大データ・不正base64・Pythonへの受渡しは未確認。

## 3. HTML比較射影の基本規則

DOMParserで作成したダミーHTML断片を使い、次の9観点で比較の期待結果を確認した。実ページのDOMを走査した結果ではない。

| 観点 | 期待結果 | 結果 |
| --- | --- | --- |
| 意味を持たないspan・リッチテキストラッパー | 同じ内容として一致 | 一致 |
| ラッパーで分割された隣接テキスト | 結合後に一致 | 一致 |
| HTMLエンティティと解析後のNBSP | 同じ文字として一致 | 一致 |
| bとstrong | 同じ強調として一致 | 一致 |
| pre/code内の空白数変更 | 不一致 | 不一致 |
| 表のセル境界変更 | 不一致 | 不一致 |
| リンク先だけ変更 | 不一致 | 不一致 |
| 画像参照だけ変更 | 不一致 | 不一致 |
| white-spaceを持つラッパーの除去 | 不一致 | 不一致 |

確認したのは基本的な構造射影であり、style・lang・dir等の属性を網羅する完成実装ではない。未知属性、URL解決、整形空白、ブラウザ補正後の表、実サイトのAPIとDOMの照合は追加検証する。元HTMLや意味のある差を無条件に削除・圧縮する根拠にはしない。

## 4. 次の確認

長いファイル名はユーザー合意によりタイトル部分だけ短縮する。アルゴリズムは[詳細設計書](detailed-design.md)5.2節、実装前の検証待ちは同14節を参照する。後続のSVG・HTML解析確認は5・6節、パス・ロックの限定確認は7節に記録する。ブラウザとPythonのデータ連携・Pillowデコードは未確認。

## 5. 静的SVGの限定確認

新たに作成した `about:blank` のタブで、固定の8×6ピクセルの単純図形と、文書内グラデーションを使うSVGを確認した。実サイトへの遷移・実SVGの取得は行っていない。

| 観点 | 結果 |
| --- | --- |
| 単純図形のXMLルート・名前空間 | SVGとして認識 |
| 文書内グラデーションのXML | SVGとして認識 |
| 壊れたXML | parsererrorとして不正判定 |
| HTMLをSVGとして扱うケース | ルート・名前空間により不正判定 |
| 単純図形・グラデーションのImage.decode | 両方成功、自然寸法8×6 |
| 外部HTTP(S)要求 | 0件。画像読込のblob要求は別扱い |

自分が作成したBlob URLを解放し、作業タブ・セッションを終了した。PythonのXML検証器、外部参照・未知構文等の拒否規則、実サイトのSVG、期限切れは未検証。全SVGの読込成功を保証する確認ではない。

## 6. 比較用templateの確認

初回のDOMParserによる比較確認に続き、記事DOMへ挿入しないtemplateで同じ基本9観点を再確認し、すべて期待結果と一致した。意味のあるテキスト差・表・リンク先・画像参照・styleを持つラッパーの差が不一致となることを確認した。

画像・iframeのダミーHTTPS参照を含む断片もtemplate内で解析し、250msの観測中にHTTP(S)要求は0件だった。万一の要求はダミーホスト向けページルートで中断するガードを置いたが、要求自体が発生しなかった。templateの内容は表示DOMへ挿入していない。

作業タブ・自分の監視・ダミーホストのルート・セッションを解放した。実サイトのHTML・入力JSONは変更していない。この限定確認を、任意のHTML・ブラウザ全般・Python実装の検証済みとは扱わない。

## 7. Windowsのパス・排他・置換

専用環境 `.venv` をuvで作成し、Python 3.15.2で標準ライブラリによるダミーファイル操作を確認した。使用バージョンは `.python-version` に記録する。アプリ用の依存パッケージはまだ導入していない。

| 観点 | 結果 |
| --- | --- |
| ハードリンクの識別 | 別の実パスでも同一ファイルとなり、`st_nlink` は2 |
| ハードリンク先のJSON置換 | 置換後は別ファイルとなり、もう一方は旧内容を保持 |
| サイドカーファイルの非待機ロック | 別Pythonプロセスの取得を拒否 |
| JSON置換中の排他 | JSONを置換してもサイドカーのロックは維持 |
| 明示的なロック解放後 | 別Pythonプロセスが取得可能 |
| ロック保持プロセスの終了後 | 自分で起動した子プロセスの強制終了後、別プロセスが取得可能 |
| 8.3短縮パス | 作成したファイルの同一性と実パスの一致を確認 |
| ジャンクション | 配下のJSONの実パス・同一性・サイドカーの生成先が一致 |
| シンボリックリンク | 作成権限不足により未確認。権限設定の変更は行わず |

ハードリンクによる別名の排他回避と置換後の分離を避けるため、ユーザー合意に基づき、複数ハードリンクを持つ入力JSONを起動時に拒否する設計へ反映した。通常のコピーを用いる運用とする。

検証対象は `%LOCALAPPDATA%/BlackLineKnowledgeCrawler/design-checks/` 配下に新規作成した一時ディレクトリだけとし、絶対パスが同ディレクトリ配下であることを確認して後片付けした。既存の入力JSON・成果物・他プロセスには操作していない。同期フォルダでの動作、実行中の参照先差替え、長いファイル名の境界、アプリ全体の排他・復旧は未確認である。

参照：[Python 3.15.2](https://www.python.org/downloads/release/python-3152/)、[msvcrt.locking](https://docs.python.org/3/library/msvcrt.html#msvcrt.locking)、[os.stat](https://docs.python.org/3/library/os.html#os.stat)。

## 8. 実記事のShadow DOM抽出と本文比較

Playwriter CLI 0.9.0でポート9223へ接続し、新規の調査用タブで既調査のPingAM記事1件を再読取した。ユニーク記事数は計4件のままである。ブラウザが発行した本文項目のAura要求と応答を同じrequest・action idで対応付け、値をメモリ内だけで比較した。追加APIの発行・再送、入力JSON更新、評価操作、ログアウト・Cookie変更は行っていない。

| 観点 | 結果 |
| --- | --- |
| リッチテキストの構造 | 4項目ともopen shadow rootがあり、ホストのinnerHTMLは空 |
| 値の抽出先 | shadow root直下のspan内部 |
| Question・Answer | APIとDOMがともに非空で、当該2項目は可視 |
| Related To・Additional Information | API値なし、抽出内容も空、当該2項目は非表示 |
| APIとDOMの構造比較 | 非空2項目と空2項目が一致。style・空白・リンク・画像参照・表構造を保持して比較 |
| Answerの表 | API・抽出内容とも1件。tbody・colspan・rowspanを含む構造が一致 |
| DOMの描画用属性 | DOM側に追加されたlwc-*属性を比較から除外。他の属性値は保持 |
| Shadow DOMの値部分の安定 | 250ms間隔の2回で一致 |
| 本文画像・表のロケーター件数 | 各1件 |
| 追加のダミー確認 | open shadow rootのホストが空でも、内部の表・非空のhidden要素を抽出できた |

比較には同じブラウザの未挿入templateを使い、spanの透明化、隣接テキストの結合、改行の統一、b/strong・i/emの同一視を適用した。結果は件数・一致可否・タグ名・属性名だけを出力し、記事本文・属性値・画像URL・認証情報は保存していない。API値と項目の対応は今回の4項目順で確認したものであり、別表示形式・任意の項目順への対応を実証していない。

ページから内容不明のエラー通知2件が出たため、ページエラーがないとは判定していない。記事の可視化と比較は成功し、調査用の応答処理の例外件数は0だった。自分の監視・調査タブ・ダミータブ・Playwriterセッションを解放した。

ログイン切れの実画面は未確認であり、判定条件は未確定のままとする。今回は認証済み記事の成功例であり、401～409・他の4xx・認証切れの優先制御、画像バイト列保存、Python版・exeの検証結果ではない。

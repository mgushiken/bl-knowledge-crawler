# 要件定義書 — BlackLine Knowledge 取得アプリ

作成日：2026-11-01

更新日：2026-11-02

状態：要件定義レビュー完了。合意済み要件と運用ルールを反映した清書版。

## 1. 目的

与えられたBlackLine KnowledgeのURL一覧をもとに、ブラウザで各URLへアクセスし、そのコンテンツをMarkdownとしてローカルに保存する。

## 2. 責任範囲

### 2.1 対象

- 与えられたURL一覧を入力として扱う。
- ブラウザで一覧の各URLへアクセスし、コンテンツを取得する。
- 取得したコンテンツをMarkdownとしてローカルに保存する。
- 記事の画像を保存し、正常完了したURLの処理状態を入力JSONへ書き戻す。

### 2.2 対象外

- Knowledgeの記事一覧からURL一覧を収集・作成する処理。この処理は別アプリ `bl-knowledge-url-list` が担当する。
- 添付ファイルの取得・ローカル保存。画像の保存は引き続き対象とする。

### 2.3 利用者・利用目的

- 利用者はユーザー本人と同じ会社のチームメンバーとする。
- 保存したMarkdown・画像はRAG用資料として利用する。

### 2.4 実行環境・配布要件

- 対象OSはWindows 11とする。
- Pythonのインストールを必要としないexeと外部設定ファイルを配布する。

## 3. 確定した機能要件

要件IDは既存の参照を維持するため、機能別の掲載順と連番は一致しない。

### 3.1 入力・取得対象

| ID | 要件 |
| --- | --- |
| FR-01 | 与えられたURL一覧を入力として、取得対象のURLを読み取る。 |
| FR-06 | 入力JSONの `urls` のうち、`is_new: true` のURLだけコンテンツを取得する。 |
| FR-27 | 取得対象URLは入力JSONに記載された順に処理する。 |
| FR-29 | URL一覧の各要素に必須項目の欠落や型の不正などがある場合は、当該要素をスキップして次のURLへ進む。不正要素のスキップは失敗件数に含め、ログに記録し、残りの対象を処理した後に異常終了する。ただし、全体停止条件を検出した場合はその時点で停止する。 |
| FR-30 | JSON全体の構文破損、`urls` 配列の欠落・型不正などによりURL一覧を読み取れない場合は、取得を開始せず、エラーを記録して異常終了する。 |

### 3.2 ブラウザ・認証

| ID | 要件 |
| --- | --- |
| FR-02 | 取得対象のURLへブラウザでアクセスし、コンテンツを取得する。 |
| FR-04 | 操作するブラウザはChromeとし、接続ポートは9223とする。 |
| FR-05 | ユーザーが事前にChromeでログインし、本アプリはそのログイン済みセッションを利用する。 |
| FR-16 | 自動ログインは行わない。HTTP 401～409の応答だけを理由にログイン切れとして全体停止せず、FR-25に従う。同じ記事の取得でHTTP 401～409とログイン画面の両方を検出した場合もスキップを優先する。HTTP 401～409の応答がなく、別の方法でログイン切れを確認した場合は全体を停止し、ユーザーがChromeで再ログインした後に再実行する。 |

### 3.3 保存内容・更新

| ID | 要件 |
| --- | --- |
| FR-03 | 取得したコンテンツをMarkdown形式でローカルに保存する。 |
| FR-07 | 記事に含まれる画像もローカルに保存する。 |
| FR-08 | Markdownファイルの仕様は参考アプリ `bl-documents-crawler` を踏襲し、記事タイトル・本文の見出し・表・リンクを維持する。結合セルを持つ表は、構造を維持するためMarkdownファイル内にHTMLの表として保持する。ただし、階層分けと `menu_path` はFR-09・FR-12を本アプリ固有の仕様として適用する。具体的な保存契約は[基本設計書](basic-design.md)に定める。 |
| FR-09 | 記事のMarkdownは保存先直下に配置し、メニュー階層によるフォルダ分けは行わない。この点は参考アプリの保存仕様から変更する。 |
| FR-10 | 廃止。添付ファイルの保存およびローカル参照への置換は行わない。 |
| FR-11 | 再実行時も、その時点の入力JSONでFR-06に該当するURLだけを取得する。正常完了または手作業による対象除外で `false` となったURLは再取得しない。対象URLに保存済み記事がある場合は、タイトル・本文・画像に変更がある場合だけ更新し、無変更の場合は既存ファイルを上書きしない。 |
| FR-12 | フロントマターの `menu_path` は記事タイトルだけを要素とする配列とし、メニュー階層の取得は行わない。 |
| FR-38 | ファイル名・パス長の上限を超える場合は、ファイル名のタイトル部分だけを短縮し、URLハッシュとフロントマター内の元タイトルを保持する。保存先自体が長すぎて短縮しても保存できない場合は、当該記事を保存失敗としてスキップする。 |
| FR-32 | 保存対象は記事タイトルと記事内の全項目（質問・回答など）とし、ナビゲーション・関連記事・評価欄などは除外する。 |
| FR-33 | 本文内の添付ファイル・ダウンロード先へのリンクは通常のリンクとしてMarkdownに保持し、リンク先を取得しない。通常のWebページのリンク先も取得しない。 |

### 3.4 入力JSONへの完了記録

| ID | 要件 |
| --- | --- |
| FR-19 | URLごとにMarkdown・画像の保存が完了した後、指定された入力JSONの該当要素の `is_new` を `false` に書き戻す。再取得して変更なしと確認できた場合も正常完了として `false` にする。取得・変換・保存に失敗したURLは、アプリでは `true` のまま残す。手作業による対象除外は4.3節に定める。 |
| FR-20 | 入力JSONへの書き戻しに失敗した場合は、エラーを記録して処理全体を停止する。保存済みファイルは保持する。 |
| FR-31 | 入力JSONへの書き戻しでは、処理が正常完了したURLの `is_new` だけを変更し、URL・配列の並び順・その他の項目と値を保持する。 |

### 3.5 実行・待機・再実行

| ID | 要件 |
| --- | --- |
| FR-13 | 入力JSONのファイルパスと保存先フォルダは外部設定ファイルで指定する。 |
| FR-14 | 1回の実行で取得対象URLを一巡して終了する。自動的な繰り返し巡回は行わない。 |
| FR-17 | 途中位置を保持する再開機能は設けない。中断後は、再実行時点の入力JSONで `is_new: true` のURLを先頭から処理し、保存済み記事にはFR-11を適用する。 |
| FR-23 | 記事の処理完了後、次の記事へ進むまで待機する。基準待機時間の既定値は180秒とし、待機ごとに既定で±10秒のランダムな揺らぎを加える。基準待機時間と揺らぎ幅は外部設定ファイルで秒単位に変更可能とする。 |
| FR-24 | 取得・変換・保存に失敗して次の記事へ進む場合も、FR-23と同じ待機を適用する。 |
| FR-28 | 取得失敗時はその場で再試行しない。次回起動時に `is_new: true` のまま残っているURLを再処理する。 |
| FR-34 | 同じ入力JSONまたは同じ保存先を使用する複数プロセスの同時実行を禁止する。 |
| FR-39 | 入力JSONが複数のハードリンクを持つ場合は起動時にエラーとし、取得・更新を開始しない。入力には通常のコピーを使用する。ジャンクション・シンボリックリンクは実パスを解決して扱う。 |

同一PC内ではアプリが排他制御する。別PCから同じ同期先・作業用JSONを同時に変更しないことは利用者の運用で守る。複数PC間の分散ロックは設けない。

### 3.6 失敗時の動作・終了結果

| ID | 要件 |
| --- | --- |
| FR-15 | 記事・画像の取得、Markdown変換、ローカル保存に失敗した場合は、その記事を未完了として扱い、エラーを記録して次のURLへ進む。失敗時点で反映済みの成果物は保持する。ただし、FR-16・FR-20・FR-26・FR-36・FR-37の全体停止条件を優先する。 |
| FR-18 | 終了時に新規保存・更新・変更なし・失敗の件数を表示し、エラーの詳細はログファイルに保存する。 |
| FR-21 | 入力JSONが読み取れ、入力不正などの失敗がなく、取得対象URLが0件の場合は、処理件数0で正常終了する。不正要素がある場合はFR-29を優先する。 |
| FR-22 | 一巡中に取得・変換・保存の失敗があった場合は、残りの対象URLを処理したうえで異常終了する。ただし、FR-16・FR-20・FR-26・FR-36・FR-37の全体停止条件を優先する。 |
| FR-25 | 記事・画像の取得でHTTP 401～409となった場合は、当該URLの記事の更新を見送り、エラーを記録してスキップする。`is_new` は `true` のまま残し、FR-23の規定待機後に次の対象URLへ進む。一巡後はFR-22に従って異常終了する。 |
| FR-26 | 記事・画像の取得でHTTP 401～409以外の4xx（400および410～499）となった場合は、エラーを記録して処理全体を異常終了し、次のURLへ進まない。当該記事の更新を見送り、`is_new` は `true` のまま残す。 |
| FR-35 | 取得対象URLに対応する既存Markdownの破損や同一URLの重複を理由に全体停止せず、再取得した内容で修復する。通常の無変更時の非上書きとは区別する。初版日時が復元不能な場合は今回の再生成日時を使用する。同一URLの重複は現在のタイトルに対応する1ファイルへ保存し、同一URLと確認できた他のMarkdownを削除する。元URLが読めない破損ファイルは保持し、取得記事を別名で保存する。 |
| FR-36 | 指定先へのエラーログ保存に失敗した場合は、代替フォルダへの保存と画面表示を試み、代替保存の成否によらず全体を異常終了する。保存済み成果物と完了記録は保持する。 |
| FR-37 | Ctrl+Cによる手動中断、作業タブ閉鎖・接続解放・一時領域の後片付け失敗は終了コード1とする。後続URLを開始せず、可能な残りの終了処理を試みる。保存済み成果物と書き戻し済みの完了記録は維持する。 |

## 4. 外部アプリとの関係・運用ルール

### 4.1 参照資料と採用範囲

- URL一覧作成アプリの要件・設計は `references/bl-knowledge-url-list/docs/` を参照する。
- 入力の実データは `references/bl-knowledge-url-list/knowledge-qa-urls.json` にある。JSONには `schema_version`、`source_url`、`article_type`、`collected_at`、`urls` があり、`urls` の各要素には `url` と `is_new` が含まれる。
- URL一覧作成アプリの要件には、Knowledgeへのアクセスにログインが必要であることが記載されている。本アプリでの認証方法はFR-05に定める。
- 参考クローラーの要件・設計は `references/bl-documents-crawler/docs/` を参照する。

Markdownファイルの仕様はFR-08により採用する。それ以外の参照アプリの動作・配布方式などは、自動的に採用しない。

### 4.2 入力JSONの状態と一覧の切替

URL一覧作成アプリの出力JSONは、同アプリが次回の一覧生成で検証する原本として変更せず保持する。ユーザーがそのJSONを別の場所へコピーし、本アプリの外部設定にはコピー先のパスを指定する。本書の「入力JSON」と、その `is_new` の自動更新・手作業による変更は、この作業用コピーを指す。原本と一覧作成アプリの管理ファイルは、本アプリで更新しない。

URL一覧作成アプリの `is_new` は、前回一覧に同じURLが存在したかを示し、コンテンツ取得の成否を示さない。本アプリでは `true` を取得対象として扱い、正常完了後に `false` へ変更する。この違いによる未取得URLの取りこぼしを防ぐため、現在の入力JSONに `is_new: true` が残っている間は、次のURL一覧を生成・使用しない。これは利用者の運用上の制約とし、別アプリによる一覧生成を本アプリが制御する機能は含めない。

### 4.3 取得を断念するURLの対象除外

取得を断念するURLについては、ユーザーがエラーログを確認したうえで、入力JSONの該当要素の `is_new` を手作業で `false` に変更して対象から外すことを認める。アプリは失敗URLを自動的に `false` に変更しない。

`false` には、一覧作成時点で新規ではないURL、本アプリで正常完了したURL、手作業で取得を断念したURLが含まれるため、値だけではコンテンツ取得の成功を保証しない。正常完了または手作業による対象除外で `true` がなくなった後、次のURL一覧を生成・使用する。

## 5. 受入条件

以下は合意済み要件から整理した確認項目であり、検証の実施結果ではない。

| 対象 | 確認条件 |
| --- | --- |
| 接続・設定 | ログイン済みChromeにポート9223で接続でき、外部設定で入力JSONと保存先を指定できる。 |
| 対象と順序 | `is_new: true` のURLだけを入力順で処理し、一巡で終了する。通常のページリンクから取得対象を広げない。 |
| 記事保存 | FR-32の範囲を、見出し・表・リンクを維持したMarkdownとして保存先直下に保存できる。命名・文字コード・フロントマターは基本設計の保存契約に適合し、`menu_path` は記事タイトルだけの配列となる。 |
| 長いファイル名 | タイトル部分だけを短縮し、元タイトルとURLハッシュを維持する。短縮しても保存できない場合は失敗記録してスキップする。 |
| 画像 | 記事の画像をローカル保存し、Markdownから相対パスで参照できる。添付ファイルは取得せず、本文内リンクを保持する。 |
| 再取得 | 変更時だけ更新し、初版作成日時を維持する。無変更時は既存ファイルと日時を維持する。 |
| 破損・重複の修復 | 全体停止せずFR-35に従って再生成する。復元不能な初版日時は再生成日時とし、同一URLの重複を整理する。元URL不明の破損ファイルは上書き・削除しない。 |
| JSON更新 | URL単位の保存完了または変更なし確認後に `is_new` を `false` にする。失敗・未処理要素と、その他の項目・値・配列順を保持する。書き戻し失敗時は停止し、保存済みファイルを保持する。 |
| HTTPエラー | 401～409は記事をスキップし、400・410～499は全体を異常終了する。画像の取得にも同じ規則を適用する。 |
| 失敗・中断 | 取得失敗時にその場で再試行しない。取得・変換・保存失敗のスキップ後も残りを処理し、失敗ありで異常終了する。401～409とログイン画面の両方を検出した場合はスキップを優先し、それ以外の全体停止条件に従う。再実行では残った `true` のURLを先頭から処理する。 |
| 待機 | 次の記事に進む前に既定180秒±10秒で待機し、失敗スキップ後にも適用する。基準時間と揺らぎ幅を外部設定で変更できる。 |
| 入力不正・0件 | 不正要素は記録・失敗計上してスキップする。URL一覧自体を読み取れない場合は取得せず異常終了する。有効な対象が0件で入力不正などの失敗がなければ処理件数0で正常終了する。 |
| 結果表示 | 新規保存・更新・変更なし・失敗の件数を終了時に表示し、エラー詳細をログに記録する。 |
| ログ保存失敗 | 代替フォルダへの出力と画面表示を試み、全体を異常終了する。保存済み成果物と完了記録を保持する。 |
| 中断・終了処理 | 手動中断と後片付け失敗は終了コード1。可能な終了処理を継続し、保存済み成果物と完了記録を維持する。 |
| 同時実行 | 入力JSONまたは保存先が同じ複数プロセスを同時に動作させない。 |
| 入力のハードリンク | 複数のハードリンクを持つ入力JSONを起動時に拒否し、ファイルやリンク構成を自動で変更しない。 |
| 運用 | 原本を保持し、作業用コピーを本アプリへ渡す。更新はコピーだけに行う。現在のコピーに `true` が残る間は次の一覧へ切り替えない。取得を断念したURLはログ確認後に手作業で `false` にでき、アプリはそのURLを取得しない。 |
| 配布 | Python未導入のWindows 11でexeと外部設定ファイルにより実行できる。 |

# 要件定義書 — BlackLine Knowledge 取得アプリ

作成日：2026-11-01

状態：要件定義中。確定事項と未決事項を区別して記録する。

## 1. 目的

与えられたBlackLine KnowledgeのURL一覧をもとに、ブラウザで各URLへアクセスし、そのコンテンツをMarkdownとしてローカルに保存する。

## 2. 責任範囲

### 2.1 対象

- 与えられたURL一覧を入力として扱う。
- ブラウザで一覧の各URLへアクセスし、コンテンツを取得する。
- 取得したコンテンツをMarkdownとしてローカルに保存する。

### 2.2 対象外

- Knowledgeの記事一覧からURL一覧を収集・作成する処理。この処理は別アプリ `bl-knowledge-url-list` が担当する。

## 3. 確定した機能要件

| ID | 要件 |
| --- | --- |
| FR-01 | 与えられたURL一覧を入力として、取得対象のURLを読み取る。 |
| FR-02 | 取得対象のURLへブラウザでアクセスし、コンテンツを取得する。 |
| FR-03 | 取得したコンテンツをMarkdown形式でローカルに保存する。 |
| FR-04 | 操作するブラウザはChromeとし、接続ポートは9223とする。 |
| FR-05 | ユーザーが事前にChromeでログインし、本アプリはそのログイン済みセッションを利用する。 |
| FR-06 | 入力JSONの `urls` のうち、`is_new: true` のURLだけコンテンツを取得する。 |
| FR-07 | 記事に含まれる画像と添付ファイルもローカルに保存する。 |
| FR-08 | Markdownファイルの仕様は参考アプリ `bl-documents-crawler` と同じにする。記事タイトル・本文を保存し、見出し・表・リンクを維持する。具体的な保存形式は基本設計書の部分草案に記録する。 |
| FR-09 | 記事のMarkdownは保存先直下に配置し、メニュー階層によるフォルダ分けは行わない。この点は参考アプリの保存仕様から変更する。 |
| FR-10 | 記事の添付ファイルは元の形式でローカルに保存し、Markdown内の添付ファイルへのリンクをローカルファイルへの相対パスに変更する。 |
| FR-11 | 同じ入力JSONの再実行でも、FR-06に該当するURLを再取得する。同じURLの保存済み記事は、タイトル・本文・画像・添付ファイルに変更がある場合だけ更新し、無変更の場合は既存ファイルを上書きしない。 |
| FR-12 | フロントマターの `menu_path` は記事タイトルだけを要素とする配列とし、メニュー階層の取得は行わない。 |
| FR-13 | 入力JSONのファイルパスと保存先フォルダは外部設定ファイルで指定する。 |
| FR-14 | 1回の実行で取得対象URLを一巡して終了する。自動的な繰り返し巡回は行わない。 |
| FR-15 | 記事・画像・添付ファイルの取得に失敗した場合は、その記事の更新を見送り、エラーを記録して次のURLへ進む。ただし、FR-16・FR-26の全体停止条件を優先する。 |
| FR-16 | 自動ログインは行わない。HTTP 401～409の応答だけを理由にログイン切れとして全体停止せず、FR-25に従う。HTTP 401～409の応答以外の方法でログイン切れを確認した場合は全体を停止し、ユーザーがChromeで再ログインした後に再実行する。 |
| FR-17 | 途中位置を保持する再開機能は設けない。中断後は、再実行時点の入力JSONで `is_new: true` のURLを先頭から処理し、保存済み記事にはFR-11を適用する。 |
| FR-18 | 終了時に新規保存・更新・変更なし・失敗の件数を表示し、エラーの詳細はログファイルに保存する。 |
| FR-19 | URLごとにMarkdown・画像・添付ファイルの保存が完了した後、指定された入力JSONの該当要素の `is_new` を `false` に書き戻す。再取得して変更なしと確認できた場合も正常完了として `false` にする。取得・保存に失敗したURLは `true` のまま残す。 |
| FR-20 | 入力JSONへの書き戻しに失敗した場合は、エラーを記録して処理全体を停止する。保存済みファイルは保持する。 |
| FR-21 | 取得対象URLが0件の場合は、処理件数0で正常終了する。 |
| FR-22 | 一巡中に取得失敗があった場合は、残りの対象URLを処理したうえで異常終了する。ただし、FR-16のログイン切れ、FR-20の入力JSONへの書き戻し失敗、FR-26のHTTPエラーによる全体停止を優先する。 |
| FR-23 | 記事の処理完了後、次の記事へ進むまで待機する。基準待機時間の既定値は180秒とし、待機ごとに既定で±10秒のランダムな揺らぎを加える。基準待機時間と揺らぎ幅は外部設定ファイルで秒単位に変更可能とする。 |
| FR-24 | 取得に失敗して次の記事へ進む場合も、FR-23と同じ待機を適用する。 |
| FR-25 | 記事・画像・添付ファイルの取得でHTTP 401～409となった場合は、当該URLの記事の更新を見送り、エラーを記録してスキップする。`is_new` は `true` のまま残し、FR-23の規定待機後に次の対象URLへ進む。一巡後はFR-22に従って異常終了する。 |
| FR-26 | 記事・画像・添付ファイルの取得でHTTP 401～409以外の4xx（400および410～499）となった場合は、エラーを記録して処理全体を異常終了し、次のURLへ進まない。当該記事の更新を見送り、`is_new` は `true` のまま残す。 |

### 3.1 実行環境・配布要件

- 対象OSはWindows 11とする。
- Pythonのインストールを必要としないexeと外部設定ファイルを配布する。

### 3.2 利用者・利用目的

- 利用者はユーザー本人と同じ会社のチームメンバーとする。
- 保存したMarkdown・画像・添付ファイルはRAG用資料として利用する。

## 4. 参照資料と確認した事実

- URL一覧作成アプリの要件・設計は `references/bl-knowledge-url-list/docs/` を参照する。
- 入力の実データは `references/bl-knowledge-url-list/knowledge-qa-urls.json` にある。JSONには `schema_version`、`source_url`、`article_type`、`collected_at`、`urls` があり、`urls` の各要素には `url` と `is_new` が含まれる。
- URL一覧作成アプリの要件には、Knowledgeへのアクセスにログインが必要であることが記載されている。本アプリでの認証方法はFR-05に定める。
- 参考クローラーの要件・設計は `references/bl-documents-crawler/docs/` を参照する。

Markdownファイルの仕様はFR-08により採用する。それ以外の参照アプリの動作・配布方式などは、自動的に採用しない。
